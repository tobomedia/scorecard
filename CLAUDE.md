# Scorecard: notes for working on this repo

Mobile web app (PWA) for keeping score while watching sport. Plain HTML/CSS/JS, no framework.
See `README.md` for deploy and setup, and `docs/MVP-SPEC.md` for the product spec.

## Always keep Help & FAQ up to date

Most changes affect how people use the app. **Every change that adds, removes, renames or changes
behaviour people see must update the in-app Help & FAQ in the same commit.**

- Content lives in one place: `const HELP = { guides, faq }` in `app.js`. The same content is
  served in the app (Help & FAQ on Home) and at the shareable link `…/#/help`.
- Check the first-launch welcome cards too (`WELCOME` in `app.js`).
- Use the exact button labels shown in the app, in `<b>…</b>`.
- Add an FAQ entry for anything likely to confuse people, including known gaps and limitations.
- `scripts/build.mjs` has a `HELP_TERMS` list. The build fails if Help stops mentioning any of
  them. Add the label of every new feature there.
- Update `docs/MVP-SPEC.md` for the same change.

## Other conventions

- Commit and push to `main`. GitHub Actions builds and deploys (`.github/workflows/deploy.yml`).
- New files the app loads at runtime must be listed in `ASSETS` in `sw.js` (the build checks this).
- Paint assets are generated by `scripts/gen-assets.py`.
- Live score server: `live/` (Cloudflare Worker + Durable Object).
- Test in a phone-sized browser (Playwright) before pushing, including iPhone SE width.
- When reporting to the user, be concise.
